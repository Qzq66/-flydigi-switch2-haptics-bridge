# 轮询与休眠分段观测候选

针对上一轮实际发送间隔中位15.278ms，新增独立`ram_pacing_loop.py`及`ram_pacing_path.py`。未修改旧冻结入口、网络协议或固件。

参数沿用已通过容量对照的30秒、最多7500查询、12ms接收预算、4ms请求休眠、all组件/1GB捕获及原空间护栏。每轮内存记录poll入口/出口、sleep入口/出口、是否接受帧；最多7500行，容量耗尽即停止，不滚动覆盖。追加记录最大开销单记；原收发观察层保持不变。额外取时也可能扰动调度，因此新结果仅作有观测层的诊断，不能直接视为未观测运行性能。

阶段数据在轮询结束后保存至本机private的`poll-phases.json`，报告绑定SHA256；异常也尽量保存已有行，然后走关闭socket、释放计时、停止捕获、回BOOTSEL及完整Flash核对流程。成功状态另要求阶段行数等于查询数且溢出为0。

7项纯模拟测试通过，覆盖已知2ms轮询/10ms实测休眠分离（请求仍为4ms）、容量耗尽前停止、查询上限、意外事件/终端拒绝、轮询中时钟倒退、无有效回复拒绝及追加开销统计。生成计划仅读取本地文件，不打开硬件。现场尚未执行，不宣称已解释15ms间隔。

现场使用原`run_pktmon_ram_capacity.ps1`捕获助手和新的pacing计划/入口；助手报告仍以PKTMON_RAM_CAPACITY命名，新程序报告为RAM_PACING_PATH。必须使用全新试次目录，不复用已结束捕获。原容量分析器只接受容量程序报告，不能直接当成新入口验收；阶段与收发联合分析需读取新报告并核对两个private轨迹哈希。

当前Pico和飞智状态未查询、未改变。下一轮只需Pico电脑BOOTSEL、原iPhone USB/2.4GHz热点、Steam退出；不接Switch、不访问飞智或输出震动。运行前仍需核对现有37代完整Flash，运行后再核对；不自动写回或恢复不同Flash。
