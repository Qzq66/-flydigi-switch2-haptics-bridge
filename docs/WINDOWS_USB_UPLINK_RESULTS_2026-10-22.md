# iPhone USB供网：电脑热点诊断与受限回放

2026-10-22。用户同意使用已有iPhone USB个人热点。当前连接为：iPhone USB → Windows电脑上网；电脑原2.4GHz热点 → Pico。已断开电脑原5GHz Wi-Fi关联，没有关闭无线网卡，没有修改驱动属性或飞智原厂持久配置。

## 诊断结论

Pico读回省电模式0，设置/读取返回值均0；原电脑Wi-Fi供网试验中Pico轮询最大停顿267µs、无超过2ms停顿，不能把网络间隔直接归因于Pico主循环卡死。

原60ms请求预算内同请求最多重发6次的候选，仅作为独立诊断包装器测试，13项离线边界检查通过。硬件对照没有改善：普通BHP2/BHI2各12秒超过80ms的间隔为4/5次，重发后为3/22次，最大171.532/183.978ms。**候选未接入生产路径，默认轮询和80ms停止保护未修改。** 证据 WINDOWS_NETWORK_TIMING_RECHECK_20261022-210024.json；前一次DHCP未完成的空测量报告也保留。

电脑AX211同时承担原5GHz上网和2.4GHz热点是待对照因素。电脑接交流电，无线电源计划交流索引为最高性能，未修改MIMO/漫游/首选频带等网卡设置。用户没有有线网络，但提供了现有iPhone USB供网。

## 网络对照结果

Windows识别Apple Mobile Device Ethernet，绑定该USB地址的TCP测试成功；一个不可达测试地址的失败未被当作USB网络不可用。切换前检查热点客户端0，停止旧热点、断开原WLAN关联，以WinRT网络适配器GUID确认共享来源为iPhone USB，再启动同一专用2.4GHz热点。证据 WINDOWS_IPHONE_USB_HOTSPOT_20261022-211128.json。

这是当前USB供网组合的良好短测证据，支持继续采用它；不能据一次顺序对照断言某个射频机制就是唯一根因，也不代表长期零丢包。
