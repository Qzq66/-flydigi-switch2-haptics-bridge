## 流式内核的范围

新文件`tools/live_fidelity_candidate.py`只提供`LiveFidelityRenderer`，没有socket、HID写入、平台适配器或实时命令行接线。原`bridge_render.py`、`bridge-switch-live.py`、`run_v042_input_recheck.py`及A/B硬件入口与冻结时哈希一致。旧提示模式保护未修改，不会自动切到新内核。

新内核状态解码每侧4字节马达字段，保持每侧低/高频的独立幅度与相位，1kHz合成、固定增益96，采用现有实验假设的64ms缓冲和5ms参数组。必须显式一次启用并有新鲜上游心跳；启用前只解码、不消耗活动或平方码预算。调用方从启用后64ms开始连续8ms块时钟，不能追赶补发。包CRC/会话/请求验证仍是既有Client的责任，不能拿本内核当完整线协议解析器。

| 限制 | 首轮候选值 |
| --- | --- |
| 活动频率 | 非零幅度分量须低于500Hz |
| 增益／峰值 | 固定96／不超过±12，保守幅度和超界直接拒绝 |
| 活动段 | 每侧最多一个活动段；双侧活动后回中即完成并永久静默 |
| 连续／累计活动 | 每侧最多320ms |
| 累计平方采样码 | 每侧不超过8000；只是数字预算，不是热模型 |
| 已启用且未完成窗口 | 15秒 |
| 网络心跳 | 80ms |
| 排队容量 | 512组 |

来源禁用、终止标记或单段双侧完成会进入静默；恢复数据不会自动重播。USB丢失、心跳失效、序号缺口、未来时间、启用后的组时间冲突、迟到参数、越界频率/幅度、超活动/剂量预算均锁定故障。中性迟到参数同样不能偷偷丢弃或移时，否则会改变包络。no-new-samples保持已有状态，不能当作停止。

正常完成时先返回最后一整块PCM，下一次`block`才返回None；未来硬件适配器须发完并留足最后8ms，再取得停止ACK。静默后只继续更新必要的心跳/USB状态，不再解码后续音频；完整队尾归档和输入转发必须由独立收集器继续，不能因为渲染停止就关掉网络或输入。这部分生命周期尚未接入实际入口，因此不能声称实时持续操控已验证。
