# Mac / Windows 分工与进度同步

更新：2026-10-21

## 环境分工

Windows 是主要开发和硬件测试环境：飞智空间站设置、固件管理、ApexSenseBridge 现成程序基线、接收器输入与音圈输出调试。这样可先建立已知可工作的设备基线，再逐步替换为自研模块。

Mac 用于协议资料、代码研究、审阅和文档维护，也可编译 Pico 固件。现阶段不以修复全部 macOS 游戏兼容作为项目先决条件。

最终独立硬件不依赖 Windows。Windows 的驱动、Engine、EXE 不能直接烧进 Pico，需要提取并移植必要的协议和纯处理逻辑。

## 统一进度记录

以 GitHub 中的代码和 `docs/STATUS.md` 为准。聊天记录不会通过 Git 同步；技术决定、反例、设置变化、实测结果与下一步应写入文档。

开始前：

```text
git status
git pull --ff-only
```

存在本地修改或历史分叉时先检查并妥善保留；禁止为了拉取更新直接强制重置。

结束时记录：测试日期、系统、硬件/固件版本、连接模式、电量、接管开关、完成项、实际通过项、失败现象、待验证项及下一步。确认只提交本次相关文件，再 commit 和 push。

切换电脑前确认已推送；另一端先拉取。尽量一次只在一台电脑推进。同一时间需要并行时，分别使用 `codex/` 工作分支，检查合并内容后再汇总。

## 当前 Mac 工作目录的历史说明

最初本地提交和通过 GitHub 连接器上传的远程提交不是同一条历史，不能假定当前旧目录能直接快进拉取。

切回 Mac 编码前，优先另建目录从 GitHub 克隆；旧目录和未同步的材料保留，不覆盖删除。不要把旧的 `windows-handoff.bundle` 导入已经克隆的新仓库。现在的新进度均以 GitHub 为准。

## Mac 探测脚本

`tools/macos_hid_probe.swift` 只匹配 `37d7:2502` 的厂商 HID collection。默认被动监听 20 秒，`--query` 仅发送身份和状态查询。无接管、配置持久化或马达命令。

```sh
swiftc -module-cache-path /tmp/flydigi-swift-cache tools/macos_hid_probe.swift -o /tmp/flydigi-hid-probe
/tmp/flydigi-hid-probe --query
```

可能需要 macOS 为宿主应用授予输入监控并重启应用；受限执行环境也可能需要其正常授权流程。不要默认需要 sudo，不关闭系统安全保护。默认不监听通用键盘 collection。输出可能含设备身份数据，分享前筛查。

## 当前优先动作

在 Windows 检查接管许可与电量，再验证按键和原生音圈输出。官方文档和 Mac 查询说明为诊断线索，不等于开关启用后功能已经验证。
