场景由用户改为《空之轨迹2nd》摇杆进门一次，不再要求B闪避/A攻击。用户已确认可以用飞智控制并进门，但进门瞬间感觉连接断开，没有额外游戏震动；明确补充连接成功时有明显短震动，断开后没有持续残留。登记阶段体感不能算游戏震动。

程序 `WINDOWS_V042_GAME_RECHECK_20261023-154932.json` 及 `WINDOWS_V042_GAME_CAPTURE_20261023-154932.json`：

- 子进程因 `calibrated prompt count cap` 退出，而非62秒live deadline。2100个8ms输出块约16.8秒，左右各3次120ms、各360个有效样本，最大偏移12。

- 子进程线程结束、计时器释放，父进程关闭确认及四区配置核对通过，无清理错误。用户确认没有持续残留。

## 用户要求增加可操作时间后的修改

根因是震动预算耗尽退出了整个PC会话，连带停止输入。保持3次/侧上限及120ms、±12不变，新增GameOutputLatch：仅针对次数上限异常执行一次停止和关闭，然后锁定静音，不再发送任何马达波形，但继续收包、采样/转发输入及完成结束握手。USB丢失、80ms心跳超时、解码及源能量异常仍传播；关闭失败仍由父进程收尾。不会自动重新启用输出。

该修改不延长固件硬时限、不重置震动次数、不写Flash；目标是恢复已有约60秒输入窗口，不能声称已支持超过60秒。带output_fault的游戏轮次仍不得通过严格游戏程序验收，即使输入和结束握手完成。登记/菜单已用完预算时后续游戏保持静音；还需后续明确分阶段安排才能单独验证游戏震动，不能靠增加输出预算掩盖它。

验证：原12组301项离线检查通过（WINDOWS_GAME_LATCH_OFFLINE_20261023.json）；新增4项锁定静音单元测试覆盖只停一次、永不重发、心跳及USB异常、其他故障传播和停止失败传播；游戏严格验收测试3组（含拒绝output_fault）与原输入结束门禁14项通过。代码尚未进行本次修改后的真机复测。

当前Pico留电脑BOOTSEL，Flash测试程序未变，最新持久日志第6代；无测试输出进程运行。原MicroPython及安装v042前完整回滚备份仍私密保存，飞智原厂配置未改。本轮新增工作尚未上传GitHub。
