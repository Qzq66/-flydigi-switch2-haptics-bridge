## Windows 先做的离线工作

1. 拉取后执行 `python tools/run_offline_checks.py`，预期十二组301项通过。保存新证据可加 `--report docs/WINDOWS_OFFLINE_RECHECK_新的时间.json`，路径须尚不存在，不覆盖旧报告。
2. 阅读STATUS及上述五份报告的验证边界。bridge_runtime是兼容入口；新增bridge_protocol/render/transport/network/windows必须一起拉取，不能只复制旧单文件。
3. 确认本机SDK2.3.1与GCC14.2.1等构建路径。工具入口使用PATH及PICO_SDK_PATH；需要时设置picotool_DIR。以--compile-only重新编译RAM与Flash可不读取真实凭据。Mac产物是占位参数编译证据，不是发布镜像。

## 硬件测试恢复后的待办顺序

仅在用户明确恢复硬件测试后执行；继续遵守原厂持久配置不修改、先备份和逐项核对、故障停止且不自动恢复的既有约束。

1. 重构后的Windows计时器、HID owner、XInput唯一槽位/人为输入确认、热点发现与父子进程停止/超时/异常清理回归。离线假对象通过不能代替物理停止。
2. v042先沿用已验证RAM路线，验证真实输入与结束收尾；保留完整脱敏事件及原始日志，避免只有307条摘要而无法回放。
3. 如进入Flash测试，先核实本机全Flash备份/恢复材料、实际4MiB板型与镜像边界；Mac已完成的只是编译，不是烧写验收。验证持久日志END2及掉线收尾。
4. 先确认原装手柄在指定游戏动作中确有震动，再验证游戏内按键与飞智提示闭环。登记页提示仍不计游戏证据；120ms固定通知不等于HD Rumble2保真。

原始Windows交接与设备状态仍见 [HANDOFF](HANDOFF_2026-10-22.md)。不要上传真实网络凭据、会话标识、设备备份或含真实参数的镜像；本次同步仅包含维护代码、脱敏报告与交接文档。
