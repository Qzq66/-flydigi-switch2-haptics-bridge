# 平台入口与子进程结果判定（2026-10-22）

本阶段仅离线开发，没有连接硬件、发送网络请求或修改设备配置。

## 修改

- `bridge-switch-live.py`、`flydigi-live-bridge-bench.py` 导入时不再加载 Windows 硬件后端。Mac 可以执行 `--help`；实际运行或直接调用硬件加载函数会明确拒绝非 Windows 平台。
- Windows 硬件依赖在真正进入硬件路径时加载；没有实现 macOS 硬件后端，热点地址与发现协议仍保持 Windows 方案。
- 提取有时限的子进程等待：超时后终止并回收，通信异常时仍尝试终止、回收。
- 父进程成功判定同时要求正确子报告、正常退出、无 error/cleanup_error/pico_reset_error；即使超时后留下成功报告也不能通过。原有独立停止和配置比对路径保留。

## 验证

`python3 tools/run_offline_checks.py --report <新的报告路径>`：十组176项通过，新增34项。报告见 [MAC_PLATFORM_VERIFICATION_2026-10-22.json](MAC_PLATFORM_VERIFICATION_2026-10-22.json)。此前142项报告保持原样。

新增测试使用假进程验证正常返回、首次超时、二次超时、通信异常、非法等待时间、退出码与报告错误；通过执行入口的帮助和Mac拒绝分支验证不加载硬件。全部测试仍在网络、动态库加载与真实子进程创建的审计拦截下执行。

这里没有启动真实受监护子进程，没有测试Windows硬件父子进程的完整整合，也没有证明物理马达停止。Windows接手后先运行离线检查，再在明确恢复硬件测试后验证：正常结束、子进程故障/超时后的独立停止、配置比对、游戏模式与结束握手。真实游戏和v042 Flash验收仍未完成。
