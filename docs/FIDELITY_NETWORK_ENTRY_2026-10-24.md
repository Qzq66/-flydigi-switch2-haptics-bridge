## 下一轮实际硬件流程

Pico与飞智都接电脑，不接Switch 2。保持飞智接收器在扩展坞、Pico在电脑直连BOOTSEL；iPhone USB共享作为电脑原2.4GHz热点上游。先正常退出Steam及其他正在输出震动的会话，松开全部按键、摇杆和扳机。无需提供网络密码。

入口会先实际比较Pico完整4MiB Flash与第20代成功快照，并备份飞智身份、状态和四区原厂配置。只接受已核验的v043快照RAM UF2：SHA256为`49acbba65eea98c1ec29a18e697c33f364111a0b2a224f56bb792067c1ce8c56`；检查SRAM地址范围与ELF无Flash擦写函数符号，然后以`picotool load -v -x`临时启动。镜像包含私密网络材料，不能上传。

RAM Pico连入原热点、会话匹配、输入全松且数据上游就绪后，电脑窗口才允许点击。45秒内未点击则不播放。点击后等6秒，期间继续收包和输入；一次片段经电脑USB注入Pico，再通过真实UDP收回并在线合成输出至飞智。只使用已验证的临时波形/运行模式与停止命令，不写持久配置。

限制沿用候选：每侧一个活动段、最多320ms，增益96、1kHz、峰值不超过±12、每侧累计平方码不超过8000，64ms缓冲、80ms心跳、15秒启用上限。注入或输出调度超出4ms直接中止，不追赶补发。实际接收抖动可能导致首轮中止，离线通过不保证Windows现场时序能通过。

收包/XInput在独立线程持续运行；输出完成后让最后8ms帧播放完整，再请求停止并等待确认。停止后至少继续0.25秒，验证至少5次输入调用及Pico输入更新计数增长，再要求RAM的ENDLAB/END2完整握手。单次事件结束后不会自动重播或恢复震动；窗口关闭或异常会触发停止，父进程140秒监护并再次停止/核对配置。

结束正常或异常都尝试让已确认身份的RAM Pico回BOOTSEL，再实际核对完整Flash与第20代快照相同。失败加载也进入恢复检查。此入口不读取完整RAM日志快照CRC，不能把UDP逐字段/握手验证描述为完整RAM日志验收。如果自动复位或完整Flash检查失败，需要按住BOOTSEL接回电脑后处理，不能直接继续下一轮。

## 本地操作入口

准备文件不接设备（现有不可变计划无需重复生成）：

```powershell
python tools/run_fidelity_network.py --prepare docs/NEW_FIDELITY_NETWORK_PLAN.json
```

硬件测试须使用明确的picotool及arm-none-eabi-nm路径；下一次设备准备确认后才执行：

```powershell
python tools/run_fidelity_network.py --play docs/FIDELITY_NETWORK_PLAN_2026-10-24.json --picotool <picotool.exe绝对路径> --nm <arm-none-eabi-nm.exe绝对路径>
```

实际报告会写入`docs/FIDELITY_NETWORK_RUN_时间戳.json`；凭据、飞智备份、工具日志与UI状态放在忽略的本地private目录，不上传。若代码或来源改变，旧计划会被拒绝，须生成新计划和新的离线报告，保留历史证据。
