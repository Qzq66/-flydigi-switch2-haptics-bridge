## 入口与已完成验证

- `tools/run_fidelity_game.py`：独立父/子进程。`--prepare`只保存计划；显式`--play`才进行只读预检、备份、监听及手动游戏测试。不会自动切换现有固定提示模式。
- `tools/fidelity_game_policy.py`：输入登记阶段静默、源马达回中等待、单次手动启用、结束后永久静默及输入继续的控制流程。
- `tools/fidelity_game_window.py`：专用UI，明确游戏内L+R/A确认、B闪避→A攻击、震动结束后摇杆验证的顺序，支持关闭窗口取消。
- `tools/assess_fidelity_game.py`：同轮程序、Flash日志、独立源重建和人工反馈的最终验收。
- [不可变计划](FIDELITY_GAME_PLAN_2026-10-25.json)与[82项离线报告](FIDELITY_GAME_ENTRY_OFFLINE_2026-10-25.json)绑定源码、V3成功报告、原输入验收及传输实现。

82项包含此前61项回放/数值检查、新游戏控制与验收16项，以及5项监听就绪检查。审计钩子禁止socket、设备动态库和子进程启动；对UI仅语法解析，没有打开窗口。候选模块导入不接硬件。已有V3证据绑定源码及冻结时的输入/传输代码哈希未变化。

新检查覆盖登记/导航及启用前活动不播放、全松与新鲜心跳门槛、单词内先活动后中性不能绕过500ms静默、一次活动的末帧排空、停止后继续归档10秒、不自动重播、取消/USB结束/心跳丢失、4ms迟到不补发、2725记录硬上限、序列/长度异常、停止后真实非中性输入证据、同轮Flash与人工反馈不可缺省，以及独立源重建不能伪造中性尾部。

## 保留的限制

| 项目 | 本候选 |
| --- | --- |
| 场景 | 《空之轨迹2nd》此前确认的下方B闪避→松开→右方A攻击，一组 |
| 渲染 | 每侧低/高频独立幅度、连续相位，固定增益96，1kHz |
| 输出上限 | ±12，每侧活动最多320ms、平方码最多8000 |
| 单次限制 | 每侧一个活动段；双侧回中完成后永久静默 |
| 启用窗口 | 最晚输入链路开始后100秒；启用后最多15秒完成事件 |
| 时序 | 64ms缓冲、实验5ms参数组、80ms心跳、4ms派发迟到即停，不追赶补发 |
| 频带/异常 | 非零幅度频率必须低于500Hz；未知状态、乱序或不适用参数中止 |
| 输入/归档 | 收包与XInput独立运行；最多2725个字段，完整保留登记前缀及停止后的报文 |

主机总输入窗口沿用已验证v043约120秒，电脑上限122秒、发现窗口120秒、父监护270秒；不是把震动连续播放120秒。源字段必须完整回中并安静至少500ms，用户按键/摇杆/扳机也需全松，才允许实际启用。没有自动增幅、补齐短震动或固定120ms提示。

## 首轮硬件测试的顺序（尚未执行）

1. Pico暂留电脑直连BOOTSEL，飞智接收器仍在电脑扩展坞，手柄开机全松；正常退出Steam等竞争会话。保持iPhone USB上游和原电脑2.4GHz热点。
2. 离线Switch 2保持一代Pro有线通信开启，用原装手柄把游戏准备到相同B→A场景，再回“手柄→更改握法／顺序”。此时仍不换接Pico。
3. 父进程实际只读核对完整4MiB与第21代快照、重新验证已成功的120秒输入/固件证据，备份飞智身份/状态及四区配置；不刷写固件。子进程完成全松检查并真正进入DISCOVERING后，才写本地就绪文件并输出监听就绪。必须等明确换接提示，不能把进程已启动等同就绪。
4. 收到明确提示后，Pico完全断电，松开BOOTSEL，经CM473接离线Switch。接收器与iPhone继续接电脑。先登记，回游戏后若出现L+R/A重新确认，用飞智完成；到战斗位置全松。此前只转发按键，不播放登记提示。
5. 电脑窗口确认源数据已安静后，手动点击“启用一次双频”。看到“已启用”后等1秒，只做一组B闪避→松开→A攻击→全松。
6. 事件完成、窗口显示停止后，等1秒再轻推摇杆验证角色仍可移动，然后全松。程序要求停止后仍有至少5秒输入读取，并有停止0.5秒之后的真实非中性操作；不能只用空读次数当作操控通过。后续源震动仍归档但不再次输出。
7. 等本轮按约190秒的既有换接安排结束，再按住BOOTSEL接回电脑，读取同轮Flash日志及人工反馈。不在这一轮中途切模式、再启用或自动重播。

本候选不由电脑擦写Flash；现有v043固件在主机运行时会正常保存下一代测试日志。因此主机试验后完整Flash预计会因日志区变化，不能套用RAM回放“完整Flash字节不变”的标准。必须证明程序/日志区外不变、此前槽保留、新增一代及CRC/完整结束正确。飞智持久配置仍禁止修改。

自制USB固件的主机/账号风险仍未得到保证；保持离线是此前采用的测试条件，不代表能够承诺零风险。首次换接前需再次提示并核对实际准备状态。本阶段没有进行这一步。

## 同轮验收与恢复

电脑端只能先给出`PASSED_SWITCH_FIDELITY_PROGRAM_PENDING_FLASH_LOG`，不据此宣称主机测试完成。成功要求：一次真实双侧活动、有界数据/派发/停止、完整终端ACK、停止后输入仍正常、最终全松、计时器/线程收尾、父进程再次停止及原厂配置一致。

用户按BOOTSEL接回电脑后，使用既有`collect_v043_host.py`只读保存完整Flash，基准为`V043_HOST_CAPTURE_20261025-141438.json`（第21代）。完整新日志应是第22代，程序及其他区域不变，旧槽保留，完整CRC、无丢失、`client_confirmed`结束。全部Flash马达字段必须与电脑完整归档逐条一致。

`assess_fidelity_game.py`再从完整前缀解码状态，按源时钟锚点和实际生成块数独立重建已输出区间，核对活动毫秒、峰值、平方码和真实中性结尾；停止后因游戏继续操作产生的报文不能算第二次已输出事件。它不制造尾部、不拿程序摘要代替源字段复算。最终还需用户确认：动作时双频触感、启用前静默、停止无残留、停止后仍能操控。

任一故障立即停止，不自动恢复震动；父监护再次停止和核对原厂配置。取消或提前退出不计成功，仍需按BOOTSEL取回本轮日志并核对。当前第21代完整快照及第20代固定提示成功档案均保留，未刷写新固件。

```powershell
python tools/verify_fidelity_game_offline.py --plan docs/NEW_GAME_PLAN.json --report docs/NEW_GAME_OFFLINE.json
```

```powershell
python tools/run_fidelity_game.py --play docs/FIDELITY_GAME_PLAN_2026-10-25.json --picotool <picotool.exe绝对路径>
```
