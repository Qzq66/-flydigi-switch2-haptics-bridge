# 可感知提示模式主机复测

2026-10-22。本轮更新电脑端渲染与 CLI，Pico 仍使用已校验的 v040 固件。Switch 2 保持离线，经 CM473 连接 Pico；飞智接收器连接电脑扩展坞。

## 已验证结果

主机 → Pico → Wi-Fi → 电脑 → 飞智的实时提示，在每侧 **120ms、样本中值 128、最大偏移 ±12** 时，用户确认：“1 这一次有明显的震动了”。选择项对应左右都能感觉到、强度舒适。

程序记录 `flydigi-live-bench-20261022-162748.json`：左右各一次完整提示、各 120 个有效样本，实际最大偏移 ±12。原始两组有效输入各为实验性 5ms；新模式将其映射为固定左 160Hz、右 320Hz 的可感知通知。因此本轮验证的是提示可感知，不是原生 HD 波形、振幅或时长的忠实复现。

Pico 本地日志 `pico-continuous-capture-20261022-163044.json` CRC 正确，303 个马达字段完整保留。电脑连续收到其中前 302 个，内容与顺序一致，两组有效震动全部到达。定时结束时最后一个中性字段 `0000000000014040` 没有回传；本轮没有声称全量无线字段完整到达。完整对照见 `bridge-v041-final-live-proof.json`，用户反馈单独保存在 `bridge-v041-final-human-feedback.json`。

子进程与父进程均确认关闭临时模式；身份、状态及全局、映射、灯光、马达四项 RAM 核对一致。未发送保存、出厂重置、配置槽选择或升级命令。

## 参数选择过程

1. 初次真实主机测试为 120ms、±3，程序完整输出，但用户未感知或认为过轻，见 `flydigi-live-bench-20261022-161338.json`、`bridge-v041-first-human-feedback.json`。
2. 持续中性帧背景下对比左 ±3、左 ±5、右 ±5，各 120ms。重播后用户确认三次都有微小震动，见 `flydigi-calibration-single-20261022-162026.json`。
3. 用户要求更大幅度后，比较双侧 ±5 → ±8 → ±12，各 120ms。用户确认都有触感但仍偏轻，并选择第三档可以采用，见 `flydigi-calibration-stronger-20261022-162328.json`。
4. 最后以 ±12 进行上述真实主机复测，获得明显震动的反馈。

±5 是此前软件测试限幅，不是手柄硬件上限。本轮通过显式参数把允许值扩至 ±12；所有旧调用仍默认限于 ±5。这里的数值是 8 位波形样本的中值偏移，不等于物理振幅百分比。

## 使用与保护

电脑端显式选择：

```powershell
python work/bridge-switch-live.py --prompt-ms 120 --prompt-offset 12
```

应使用本机已验证的 Python 与 HIDAPI 环境。该命令只启动电脑接收器，运行前须准备测试热点、安装已校验 Pico 固件，并按已验证流程人工换接；当前 Pico 已恢复原 MicroPython，不能直接换接后期待桥接运行。

默认不传参数仍是原始实验性渲染。`bridge-perceptible-profile.json` 仅记录已验证参数，不会改写手柄配置，也不会自动更改 CLI 默认值。

提示模式每侧每轮最多三次，重叠有效输入不延长当前提示；主机关闭震动、USB 停止、80ms 心跳超时、校验/时序异常均取消输出，故障不会自动恢复。程序继续保留当前短测的源有效样本时限，不适用于持续游戏震动。电脑父进程独立负责超时关闭及配置复核。

软件验证包括原模式 18 项检查和提示模式 16 项检查，见 `bridge-v041-original-runtime-tests.json`、`bridge-v041-prompt-tests.json`；另有上轮 303 字段的离线提示回放 `bridge-v041-captured-prompt-simulation.json`（该离线回放使用 ±3，并非本轮 ±12 的物理验证）。
