# v040 实时桥接验证记录

日期：2026-10-22。飞智接收器在电脑扩展坞，Pico 使用电脑直连接口或经 CM473 接离线 Switch 2。

## 已完成

- 实际硬件路径：电脑注入已采集的 Switch 原始报文 → RAM Pico USB → 2.4GHz Wi-Fi → 电脑解码 → 飞智临时波形输出。
- 最终报文测试 `pico-bridge-v040-raw-test-20261022-153613.json`：306 条事件连续、300 条注入数据逐字节一致、0 重复、0 溢出；USB 输入保持响应，自动发现和一次 L+R 登记通过。
- 物理输出测试 `flydigi-live-bench-20261022-153429.json`：484 个 8ms 输出帧，左右各 5 个有效样本，实际最大偏移为中值 128 的 ±3（硬限制 ±5）。使用 Windows 高精度计时器、固定连续样本时钟。此结果是电脑重放原始报文的桥接台架测试，不能替代真正的 Switch 实时测试或主观反馈。
- 子进程和独立父进程均确认关闭临时震动模式；全局、映射、灯光、马达四项 RAM 及当前状态核对完全一致。未发送保存、恢复出厂、配置槽选择、固件更新命令。
- `bridge-v040-runtime-tests.json`：18 项软件检查通过，涵盖校验、会话、源溢出处理、心跳、USB 失联、频率限制、能量时限、迟到片段、不连续样本时钟及延迟处理停止。

## 修正与边界

首次台架测试使用实际唤醒时间作为每块起点，导致一个很短的左侧片段未渲染。改为严格连续的 8ms 样本时钟，并使用 `perf_counter`；迟到的有效片段直接停止，不追赶补播。部分入网测试失败，固件现在只在首次会话前进行最多三次入网尝试，已开始输出的会话不会自动恢复。

协议分组每 5ms 渲染仍是实验假设，未测得任天堂原始分组生成时钟。渲染缓冲 64ms，1kHz PCM；有效频率达到 500Hz 时停止。单侧连续有效样本最多 40ms、累计最多 100ms，适用于本轮短提示，不适合游戏持续震动。无线心跳超过 80ms、源队列溢出、序号缺失、设备重启或 USB 停止均锁定停止。

## 主机测试

执行入口 `work/bridge-switch-live.py`。电脑接收器通过定向广播发现本次会话的 Pico，不依赖上次 DHCP 地址。父进程先备份飞智配置；子进程在等待之前完成完整核对，最多等待 120s 发现 Pico；进入实时阶段后最多 22s，父进程总上限 155s。Pico 在无线及 USB 就绪后记录 20s，总通电上限 60s，自动停止无线、断开 USB、保存一次日志并进入 BOOTSEL。

主机测试须保持离线及“一代 Nintendo Switch Pro 手柄有线通信”开启。Pico 模拟 Pro 接口；无需另一只实体 Pro 手柄，也无需切换飞智模式。主机或账号风险未验证，离线不等于零风险。

## 真实 Switch 测试与最终状态

第一轮电脑等待窗口结束前没有发现 Pico；主机本地日志确认 USB 已初始化但未触发登记。随后同一 Flash 固件在电脑上成功入网、回复 UDP，故未将该现象归因于 USB 识别失败。第二轮收到 277 条无线事件，主机出现图标，但完整配置核对位于握手之后，耽误了短提示播放。已把完整核对移到发现等待之前，并增加接收与处理时间分离的过期检测，避免静默跳过有效短片段。

最终真实主机测试 `flydigi-live-bench-20261022-155010.json` 通过受限实时转发与配置核对。独立本地日志 `pico-continuous-capture-20261022-155322.json` 与无线接收的 303 个马达字段顺序及内容完全一致，没有缺包或溢出。左右各 5 个有效样本，2 个非中性波形帧，实际最大偏移 ±3；两进程关闭确认成功，四项 RAM、状态和身份完全一致。核对证据为 `bridge-v040-switch-live-proof.json`。

用户确认出现图标，但没有感觉到震动；记录见 `bridge-v040-human-feedback.json`。因此当前结论仅为：真实 Switch → Pico → Wi-Fi → 电脑解码 → 飞智临时输出的数据链路已通过。本轮不证明体感效果，也不证明完整游戏体验或高保真复现。下一步应单独做可感知的短震动校准，仍不修改飞智持久配置。

完成日志取回后，Pico 已恢复原 4MiB Flash并全量校验通过，MicroPython COM11 的 10 次 REPL 验证通过，见 `pico-capture-restored.json`。专用临时热点已撤下，原热点的 SSID、密码、频段及原开启状态恢复并核对通过，见 `pico-hotspot-restored.json`。当前直接换接 Pico 到 Switch 不会运行桥接，须按已校验镜像重新安装后启动电脑接收程序。
