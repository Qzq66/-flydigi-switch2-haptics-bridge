# 受限回放与无线链路首测

2026-10-22。用户提供创客版 Pico 2 W 照片、规格表及淘宝短链。照片可见 RP2350 与 Pico 2 W 布局，无线芯片位于无可读型号的屏蔽罩内。商品“2MB Flash”仍与先前 JEDEC/SFDP 及全量读回确认的 4MiB 不符，继续采用实际测得容量。

## 受限离线回放

从第六轮完整日志的两个有效提示样本生成 192 ms、24 个 8 ms 数据块。左右先后及接收时刻间隔保留至 1 ms，采用明确标注的实验性 5 ms/参数组渲染，并加中性尾段。该时长不是对主机内部采样钟的测量，也不是原触感还原保证。实际采样偏移最大 3 码，低于先前测试的 5 码上限。

首次运行未发现接收器，输出前退出；用户将接收器与手柄接回后执行一次。先备份、子进程输出、父进程超时守护及收尾停止。停用命令第一次应答成功。全局、映射、灯光、电机四份 RAM 逐字节相同，身份及当前状态相同，无持久写入命令。

证据：flydigi-captured-replay-20261022-142619.json、对应 backup 文件、switch2-captured-replay-plan.json 与 proof。主机提交时刻最大偏离计划约 1.692 ms，见 flydigi-captured-replay-timing.json；这不是实测电机播放延迟。未获得本次主观触感反馈，不能由接口发送成功断言用户已感觉到这些极短提示。

## 无线硬件兼容探测

原厂 MicroPython 可读有效 MAC，但 active(True) 后仍返回 False，未据此判断硬件损坏。随后采用 Pico SDK 2.3.1 指定的 CYW43 驱动提交 055d64274b014dd7b1c2fc94d26e8a18face7124，构建独立 RAM 诊断，标准 Pico 2 W 引脚配置成功初始化，并读取无线固件版本：7.95.49，FWID 01-c51d9400。证明标准 CYW43 驱动及接线兼容；没有拆除屏蔽罩核实裸芯片丝印，也不据此认证板子为官方原装。

诊断有硬件看门狗和自动退出；仅读无线固件版本，不加入网络、不保存凭据，结果 pico-wifi-c-probe.txt。之后恢复原始 MicroPython。构建源码 outputs/pico-wifi-ram-probe，脚本 work/build-pico-wifi-probe.ps1、run-pico-wifi-probe.ps1。

## 电脑移动热点与实际 UDP 测试

用户选择电脑移动热点。起始热点已经 On、Band Auto、其他客户端 0，已备份原状态并调整为 TwoPointFourGigahertz，名称、密码不变。本机热点地址 192.168.137.1；凭据仅以当前 Windows 用户 DPAPI 加密存于 work/private（目录设置 .gitignore）。热点密码未显示到聊天、未嵌入固件镜像，也未写入 Pico Flash，仅经已核对身份的 USB 通道传入运行内存。

SDK 固定 lwIP 提交 77dcd25a72509eb83f72b033d219b1d40cd8eb95。初次 5 秒连接超时；增加目标热点扫描、分阶段状态及 20 秒连接上限后成功，不能仅据此认定首次失败的唯一原因。扫描发现目标热点，RSSI -22 dBm、通道 6，连接状态 3，Pico 获得 192.168.137.64。

PC 主动查询 Pico UDP 49723，回复携带每次会话标识、序号、Pico 微秒时间戳、已知诊断负载和 CRC32。测试不含手柄数据、不执行输出。采用请求/回复，不新增入站防火墙规则，也没有关闭防火墙。错误会话标识请求未获回复。CRC/会话字段用于本轮诊断隔离，不是经过认证的完整远程执行协议。

结果 pico-wifi-udp-20261022-145259.json：300/300 成功，0 丢包、0 CRC 错误、0 负载错误，源时间戳严格递增。RTT 最小 1.034 ms、中位 1.690 ms、P95 38.436 ms、最大 47.508 ms。统计包含 Windows 调度、请求轮询与无线往返，不能视为单向延迟或电机播放时间。当前尾部抖动明显，尚未验证对持续震动的影响。

源码 outputs/pico-wifi-udp-ram；运行脚本 work/run-pico-wifi-udp.ps1，客户端 work/test-pico-wifi-udp.py。连接使用 RAM 镜像、有看门狗、60秒总寿命和显式退出；结束关闭无线并回原始 MicroPython，10 次 USB 通信检查正常。Pico Flash 未改写。电脑热点按用户选择保留开启、2.4GHz，用于后续链路工作；原 Auto 配置已备份。

## 当前边界与后续

已完成离线受限回放及 Pico 到电脑的真实无线数据链路，尚未合并 Switch USB Pro 与无线传输，也未把无线数据送入飞智实时输出。两个通路分别通过不代表完整桥接完成。后续需要完整的报文队列/序号处理、超时停机和断线禁止自动恢复策略，以及无线抖动测量。
